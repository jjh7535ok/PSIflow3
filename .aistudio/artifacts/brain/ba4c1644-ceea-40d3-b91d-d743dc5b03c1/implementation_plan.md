# 품목 마스터 영구 저장 및 구글 소유자 인증 동기화 계획서

신규 부품 등록, 수정, 삭제 후 새로고침이나 공유 링크를 열었을 때 데이터가 저장되지 않고 초기화되던 치명적인 원인을 근본적으로 해결하고, 지정된 구글 소유자 계정(`jjh7535ok@gmail.com`)으로 접속 시 모든 변경사항이 서버와 브라우저에 즉시 영구 저장되도록 개편합니다.

---

### User Review & Critical Decisions

> [!IMPORTANT]
> **확인된 저장 실패의 3대 핵심 원인**:
> 1. **URL 해시 스냅샷의 강제 덮어쓰기**: 주소창 끝에 `#week=...`나 `#snapshot=...`이 남아 있는 상태에서 페이지를 열면, 브라우저가 최신 수정 내역을 무시하고 링크 생성 시점의 옛날 스냅샷으로 무조건 되돌리는 버그가 있었습니다.
> 2. **Firebase Auth 토큰 캐시 누락으로 인한 소유자 권한 해제**: 새로고침 시 Firebase Auth는 사용자 세션을 복구하지만, 메모리 변수(`cachedAccessToken`)가 비어 있어 `isOwner`가 `false`로 풀리고 저장 로직(`if (!isOwner) return;`)이 차단되었습니다.
> 3. **서버 저장소 부재**: 데이터가 브라우저의 임시 `localStorage`에만 머물러 있어, 다른 브라우저/기기에서 열거나 캐시가 비워지면 초기화되었습니다.

- **확정된 방향 1 (서버 영구 저장소 `/api/workspace` 신설)**: 품목 마스터나 일자별 수치 수정 시 브라우저뿐만 아니라 백엔드 서버 디스크(`.workspace_data.json`)에 실시간 영구 저장합니다.
- **확정된 방향 2 (소유자 인증 세션 완벽 복원)**: `jjh7535ok@gmail.com` 계정으로 한 번 로그인하면, 새로고침이나 재접속 시에도 소유자 권한(`isOwner = true`)이 끊김 없이 유지됩니다.
- **확정된 방향 3 (스냅샷 우선순위 역전 방지)**: 소유자가 접속 중일 때는 URL의 과거 스냅샷보다 **서버의 최신 저장 데이터가 최우선으로 로드**되도록 개선합니다.

## 1. Overview & Core Concept

- **What It Does**:
  - 품목 마스터(`ProductMasterView`)에서 부품을 추가하거나 삭제, 수정하면 0.01초 만에 로컬 상태와 서버 영구 파일에 동시 기록됩니다.
  - 구글 로그인 버튼을 통해 `jjh7535ok@gmail.com`으로 인증된 소유자에게는 화면 상단에 `👑 소유자(수정·배포 권한)` 배지가 항시 유지되며, 모든 수정 권한이 완전히 개방됩니다.
  - 외부 공유 링크를 발급할 때도 최신 마스터 데이터가 실시간 반영된 주소가 생성됩니다.

## 2. Technical Architecture & Data Strategy

```
┌────────────────────────────────────────────────────────┐
│                   User UI (React 19)                   │
│   - ProductModal (등록/수정) / Delete (삭제)            │
│   - MatrixGrid (수치 셀 인라인 수정)                   │
└───────────────────────────┬────────────────────────────┘
                            │
              handleSaveProduct / handleDelete
                            │
        ┌───────────────────┴───────────────────┐
        ▼                                       ▼
┌─────────────────────────┐           ┌─────────────────────────┐
│ Client-side LocalStorage│           │ Backend Server (Express)│
│ (즉시 화면 반영 & 오프라인) │           │ POST /api/workspace     │
└─────────────────────────┘           │ (.workspace_data.json)  │
                                      └─────────────────────────┘
                                                ▲
                                       새로고침 / 재접속 시
                                       GET /api/workspace
                                       (서버 최신본 자동 복원)
```

### 1) 백엔드 영구 저장 API (`server.ts`)
- `GET /api/workspace`: 서버 디스크의 최신 품목 마스터(`products`), 일자별 데이터(`dataStore`), 라인 구성(`lines`) 반환. (파일 없을 시 기본값 안전 생성)
- `POST /api/workspace`: 소유자의 변경사항을 서버 디스크(`.workspace_data.json`)에 영구 기록.

### 2) 인증 모듈 고도화 (`src/services/googleAuth.ts`)
- `initAuth` 함수에서 구글 인증 복원 시 토큰 캐시 유무와 무관하게 `user.email.toLowerCase() === 'jjh7535ok@gmail.com'`이면 즉시 `isOwner = true` 보장.
- 브라우저 로컬 스토리지에 마지막 인증 이메일을 캐싱하여 초기 렌더링 시 깜빡임(Flicker) 차단.

### 3) 상태 로드 우선순위 정상화 (`src/App.tsx`)
- 페이지 로드 시:
  1. 서버의 `/api/workspace`에 저장된 최신 데이터 조회.
  2. 만약 소유자가 아닐 때에만 URL 해시(`#week=...`)의 읽기 전용 스냅샷 반영.
  3. 품목 저장/삭제 시 즉시 서버 API 호출로 백업 동기화.

## 3. Verification Plan

1. **품목 추가 후 새로고침 검증**:
   - 신규 부품(예: `TEST-PART-01`)을 추가하고 F5(새로고침) 후에도 목록에 정상 유지되는지 확인.
2. **품목 삭제 후 새로고침 검증**:
   - 기존 부품을 삭제하고 브라우저를 껐다 켜도 삭제된 상태가 서버에 영구 유지되는지 확인.
3. **공유 링크 발급 검증**:
   - 신규 추가된 부품이 [주차별 링크 공유] 생성 시 링크에 정상 포함되어 상대방에게 전달되는지 확인.
4. **소유자 권한 지속성 검증**:
   - `jjh7535ok@gmail.com` 로그인 상태에서 브라우저를 닫았다가 다시 열어도 소유자 권한이 즉시 복원되는지 확인.
